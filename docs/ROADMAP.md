# ROADMAP — 产品迭代路线图

> 创建于 v0.19.0 之后（2026-08-26）。定位：微信原生团队待办，差异化 = 轻量协作 + 离线可用 + 微信生态触达。
> 版本节奏参考历史：小步快跑，一个版本 1-2 个功能点。

## 五大演进轴

| # | 轴 | 一句话 | 现状 |
|---|---|---|---|
| A | 提醒闭环 | 从单点到期的提醒做成「到期分级 + 每日晨报」体系 | 链路代码已就位，只差模板 ID |
| B | 任务模型加深 | 子任务清单 / 循环增强 / 附件 / 验收流 | 扁平模型（标题+指派+时间） |
| C | 视图扩展 | 日历 / 看板 / 全局搜索 / 我的一天 | 仅列表视图 |

| E | 数据洞察 | 团队健康度报告、导出增强 → 未来商业化分层 | 有周报热力图 + 个人档案 |

## 0.20 拆解：订阅消息闭环 + 晨报推送

### 前置（人工，阻塞项）

- [ ] **mp 后台申请两个订阅消息模板**：
  1. 「任务提醒」：thing(待办标题) + time(截止时间) + thing(备注) —— remind-cron 已按此字段写死
  2. 「每日晨报」：thing(今日概要) + number(今日件数) + time(日期) 或同类组合（以可选字段为准微调）
- [ ] 模板 ID 到手后：填 `utils/config.js SUBSCRIBE_TMPL_IDS` + `supabase secrets set WX_TEMPLATE_ID=...`（及晨报 ID）

### 产品约束（必读）

**订阅消息是一次性授权制**：用户授权一次 = 可接收一条。对每日发的晨报意味着——

- 触达率上限 = 用户近期授权次数。策略：
  - 高价值时机请求授权：创建待办时（已有 create-todo.js:256）、首次完成任务后、消息中心空态引导
  - 授权成功提示文案强调「开启后每天早上收到今日待办」
  - 后续版本可加设置页开关，管理授权引导频率
- 到期提醒同理省着发：同一待办同一人只推一次，避免烧授权次数

### 代码侧任务

**客户端**
- [ ] config.js 填入模板 ID 后真机验证授权弹窗（notify.js requestRemindPermission 已封装）
- [ ] 新增授权时机：任务完成后 toast 引导（轻量，不打扰）
- [ ] 晨报偏好：profile 页加「每日晨报」说明入口（v1 只做说明+授权引导，不做服务端开关）

**云端（remind-cron 扩展）**
- [ ] 抽公共模块：access_token 获取+缓存、openid 查询、sendSubscribe 封装
- [ ] 到期提醒去重：记录已发送 (todo_id, member_id)，防 pg_cron 每 5 分钟重复轰炸
- [ ] 新增晨报逻辑：每日 8:00±5min 窗口触发一次，查「今日 due_date 且未完成」按成员聚合，一条汇总消息
- [ ] 防重：晨报按 (date, member_id) 记录已发；用 profiles 表加字段或独立 cron_log 表
- [ ] 部署 + 用测试 openid 验证两条链路真实到达

### 验收标准

- 双设备：A 创建明日到期任务指派 B → B 收到授权后次日收到提醒，且不重复
- 晨报：今日有 2 件事的用户早上收到一条汇总；无任务用户不打扰
- 授权次数耗尽时静默降级（发送失败不报错堆积）

## 度量（发布后观察）

- 晨报授权率（授权人数/DAU）、晨报点击 → 打开小程序转化
- 提醒消息到达后的任务完成率对比
- 分享卡片带来的新增团队数（现有情境邀请继续观察）

## 明确不做（现阶段）

- Realtime WebSocket（30s 轮询够用，双设备实测后再评估）
- 安卓/iOS App、Web 端
- 多语言
